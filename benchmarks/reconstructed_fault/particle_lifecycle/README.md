## Changes and ownership

- The native particle manager backs up/restores its population RNG **and** the
  generator-base random-placement RNG with particle state. Point-density minimum
  selection, histogram choices and random removal use the manager stream;
  random insertion uses the generator stream. Initial random-uniform/PDF seeding
  uses a temporary generation stream, not a later population-management stream.
- Manager archive version 1 stores both streams per rank, per manager. Gathering
  occurs in the established all-rank pre-checkpoint hook. Serialization itself
  contains no collective. Same-build/count/partition replay is qualified. Legacy
  snapshots without streams and changed MPI counts explicitly reject active
  addition/removal; disabling population changes permits unrelated restart with
  a clear replay-unavailable diagnostic. Arbitrary repartition replay is not claimed.
- Three generic notifications expose completed particle backup, restore and count
  management. The BP3 plugin follows these lifecycles; the simulator retains
  acceptance/rejection ownership. Existing solver splitting hooks keep their timing.
- The maintained H audit captures initialized birth H before mechanics, checks
  survivors exactly, removes obsolete entries and restores its backup on rejection.
  Only owned/ghost IDs plus one backup persist during stepping. Native auxiliary
  transfer carries baselines across MPI migration. The checkpoint hook gathers
  current owned baselines to rank zero; version-6 BP3 output archives save that
  current population plus the next-ID threshold. Load checks/prunes the temporary
  global snapshot. Version-5 maps are readable and pruned too. No physical particle
  property, analytical birth reset, or second constitutive update was added.
- `particle_policy.prm` is shared by the local fixtures and the separate production
  lifecycle candidate: regular 4×4, min/max 12/24, native point-density management.
  The maintained native-LLS wrapper resolves `crack_driving_force` (0) and `maxwell
  stress` (3–5) from runtime names, validates component counts, limits both and
  disables boundary extrapolation. It logs each resolved field once. The fitting,
  limiter, Q2 fields, filter20, physical parameters and solver tolerances are unchanged.

The native additional-data callback API did **not** include its payload in this
build's mesh checkpoint path. The first audit restart failed and was corrected
with the explicit current-population checkpoint capture above. No library or
production GMG/domain algorithm was changed. Checkpoint capture/load has temporary
O(global current particle count) memory; its production-scale peak is not measured.
