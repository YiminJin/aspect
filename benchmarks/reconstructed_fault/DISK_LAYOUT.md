# Reconstructed-fault disk layout

Storage cleanup completed 2026-10-09 in the existing `fault-propagation` worktree.
It reclaimed **1.70 GiB**, without changing scientific source, fixtures,
results, failed qualifications or benchmark entry points.

Existing benchmark scripts, PRMs, CMake inputs and evidence stay at their original
paths. The 137 MB time-comparison evidence and the failed trajectories remain
scientific records, so they were retained. Python bytecode caches were removed.
No production code, parameters, H/phase law, manifests or evidence tolerances changed.

## Build artifacts

The current executable, plugins, CMake configuration and compiler provenance remain
in their existing build directories. `build-propagation-integration/` now groups
artifacts as follows:

| Physical directory | Contents |
|---|---|
| `runs/` | Historical and current native run outputs, including failures and checkpoints |
| `archive/baselines/` | Immutable incoming-state snapshots |
| `archive/executables/` | Saved native FE executable variants |
| `CMakeFiles/`, `plugin/`, root executable | Active build configuration and runnable binaries |

Original `output-*`, `*-baseline` and saved-binary directory names are relative
compatibility symlinks. Existing scripts and file hashes therefore remain usable
without path edits. No internal relative symlinks existed in the moved trees.

Identical files share storage **only between immutable snapshot copies**. Those
files are read-only; they are not linked to writable source, current executables,
plugins or live run outputs. To restore an editable snapshot copy, use a normal
copy or reflink, never `cp -l`; do not edit archive files in place. If a temporary
writable copy is required, copy it first, then change permissions on that copy.

## Removed and retained

121 regenerable files (1.08 GiB) were
removed: CMake object files, the precompiled header, Python bytecode and the
oversized generated `build-propagation-p1/cmake_install.cmake`. Another
0.61 GiB was recovered by sharing identical
archive copies. No manifest-pinned file or tracked file was deleted.

All executables and shared libraries remain; existing runs can use them. The next
compilation must rebuild missing objects and the precompiled header, which will
use disk space again. Existing CMake caches retain the actual compiler/dependency
configuration. Before installing from the old P1 test build, regenerate its deleted
installation script with `cmake -S tests -B build-propagation-p1`; this task did not
reconfigure or rebuild it.
