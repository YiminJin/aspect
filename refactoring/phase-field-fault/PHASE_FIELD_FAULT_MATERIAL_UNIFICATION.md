## 4. Keep parameter compatibility local

The present `fault_parameters.cc` reconciles explicitly supplied inputs across subsections, including parameters registered by external laws. Physical declarations belong with the material, phase model or resistance law that owns them. Retain the actual compatibility code that is still needed under a descriptive owner such as `material_model/phase_field_fault/input_compatibility`. If the remaining logic becomes small, fold it into the owning implementation. Keep fault-specific parsing out of the general material interface.

In particular, preserve omitted versus explicitly supplied defaults, conflicts, equivalent numeric spellings, and external laws with nested parameters. The historical `growing fault` spelling ignores `Simple model / Viscosity` for the growing Maxwell law. The canonical `phase field fault` input currently accepts it as a viscosity alias. The identical C++ material must still honor both input contracts.

Try to remove the fault-specific viscosity observer in `source/material_model/interface.cc` using the actual declaration and parsing order on supported deal.II versions. If a small post-declaration hook is necessary to observe an explicitly supplied upstream default, retain and justify the minimum existing hook. Moving the parser into `interface.cc`, redistributing it through upstream core files, or changing parameter semantics to remove that hook would be a worse result.
