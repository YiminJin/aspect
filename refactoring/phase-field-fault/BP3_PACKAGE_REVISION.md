## 1. Give ASPECT a reusable, opt-in fault RSF timestep model

In `bp3_qd.cc:106–127`, `BP3TimeStep` chooses the minimum of `0.1 Dc/V` and `0.1 Θ` over accepted mature labels. Its retry uses the same accepted parent. The second expression is a timescale in seconds. Both caps together give a conservative bound at frozen speed, but neither measures the age change produced by an accelerating trial.

Add the timestep plugin in the ordinary `include/aspect/time_stepping/` and `source/time_stepping/` locations. Move constitutive queries to the owning material or resistance law where appropriate. Read the active law's slip distance and age through that interface, which must work for the BP3 spatial RSF subclass. Remove the benchmark timestep registration and update both parameter files through their shared include.

Use two independent dimensionless controls. In the first revised BP3 input explicitly set both to 0.1, so the change in the state criterion can be evaluated without also changing the nominal slip resolution. Document the separate meanings and the off/default behavior. Preserve existing timestep behavior in inputs that do not select the plugin.

- **Slip resolution.** For a constant-speed prediction require `|V| Δt / Dc ≤ C_slip`. At acceptance use the slip increment consistent with the route's discretization. Zero speed contributes no slip restriction. Take the most restrictive applicable location and compose with ASPECT's other timestep controls.
- **State resolution.** Require `|ln(Θ_new/Θ_parent)| ≤ ε_Θ`. Age remains stored in seconds. Predict with the current law's exact constant-speed `RateAndStateFriction::advance_age` using the accepted parent, with its existing zero-speed limit. Bound or solve for an admissible duration without changing material history. Use a numerically safe log ratio and validate finite, positive ages. At steady sliding the state restriction is inactive even though the slip resolution still applies.
- **Proposal and acceptance.** Trace `time_stepping_manager.update()`, `determine_reaction()` and `post_accept_timestep`. Distinguish the completed trial, its parent and the proposal for the following step. For a converged trial, enforce the configured limits against the proposed endpoint increments **before** publication. Reuse the rate, duration and update the owning solver will commit. When a limit is exceeded, request a strictly smaller retry via the existing manager. Do not commit age, slip, diagnostics or output on a rejected attempt. Handle zero-duration initialization, solver failure without a valid candidate, restart and MPI replicas/owners explicitly. A converged nonlinear solve alone does not establish timestep accuracy.
- **Applicability.** Use the native mature labels and growing strip histories, including signed strip rates through their magnitude for aging. Growing uses a midpoint stage and a full-duration publication; preserve its separate constitutive admissibility and retry checks. Define which strip states participate from the actual evolution and formation rules. A state-free law supplies no age constraint. Apply a slip limit only where the law supplies a meaningful characteristic slip distance. Preserve standalone operation of those laws and avoid manufacturing dummy histories. Reuse the same limiter for a stateful law with a stationary or advected mature trace through persistent IDs.
- **Historical comparison.** The donor's `source/time_stepping/reconstructed_fault.cc` predicts logarithmic age changes. Its separate operator-split slip criterion in `source/material_model/rheology/fault_friction.cc` uses `CFL × (a/b) Dc/V` where applicable, and the old BP3 input used `Maximum logarithmic state change = 0.2`. The proposed all-station slip budget is an accuracy choice for this branch. Keep the donor stability argument distinct in the documentation.

Verify a steady-state case, healing and decreasing age, and an accelerating trial where the parent proposal passes but the endpoint fails. Check that the accepted retry agrees with a clean run taking the same smaller step. Exercise the growing RSF route and state-free compatibility with existing small fixtures. For BP3, compare a short accelerating interval with tightened tolerances when one is available. The 900 s startup alone cannot select a production tolerance for rupture.

## 2. Use the standard box and startup refinement

Remove `BP3Box` and its geometry registration. Preserve the dimensions, 40 × 18 coarse repetitions, boundary IDs, 60° loading, and the static phase profile. The original four refinement passes select every cell whose *extent* intersects the strip of signed normal distances `[-1500,1500]` m. The 250 m profile width and 2250 m mechanical association radius serve different purposes.

The ordinary ASPECT startup loop in `source/simulator/core.cc` marks cells on each initial global refinement pass, calls `tag_additional_cells()`, then refines before setting the initial fields. Use `Model name = box`, four initial global passes, zero initial adaptive passes and zero subsequent refinement. Use the built-in `maximum refinement function` with Cartesian coordinates to clear flags outside the band. This works with the material's fixed-mesh requirement. Keep its admission check.

For the existing rectangular mesh let `H = 40000 sin(60°)`, `r = sin(60°) x + cos(60°) (y−H)`, and `b = 1500 m`. At level k the code's corner-intersection test is equivalent to testing the center against

```
|r_center| ≤ b_k
b_k = b + [sin(60°) (80000/40) + cos(60°) (H/18)] / (2 × 2^k).
```

The thresholds at levels 0 to 3 are approximately 2847.151, 2173.575, 1836.788 and 1668.394 m. Specify the maximum permitted level as 4 inside the narrowest threshold, then 3, 2, 1 and finally 0 outside the widest. Derive the constants from the geometry and document the expression in the prm. An independent comparison of the two raw predicates agreed on all 61,200 possible cells over those four levels. Verify the actual distributed, balanced mesh: compare sorted active CellIds by level or equivalent footprints, the two boundary contacts, finest cell sizes (~125 × 120.28 m), phase and initial station rates. Check one and two ranks. If the actual mesh differs, locate the difference before revising a reference.

## 3. Write native visualization when cumulative slip advances

Enable the standard `visualization` postprocessor in both pilot and production, including the pilot's overriding list. Use the existing VTU/PVTU/PVD writer and expose velocity, pressure, phase and the three physical stress fields (`fault_tau_xx`, `fault_tau_yy`, `fault_tau_xy` via the existing `named additional outputs` selection). Preserve the small station histories on every accepted step. Confirm the arrays and times by reading the output.

For the mature fault, let `U_i` be the accepted cumulative slip in metres at persistent material ID i. Save the values at the **last actual graphical frame**. Write on the first accepted frame and whenever `max_i |U_i(now) − U_i(last frame)| ≥ ΔU_vis`. Use all fault labels. This detects a moving rupture and slow accumulation over many steps. It is a net signed-slip difference per ID where signed slip is supported. Keep growing-geometry semantics explicit if exposing the output option there.

- Make the threshold configurable in metres and the trigger opt-in. Retain ordinary time/step output as alternative triggers, with one frame if several triggers coincide. Use a documented sparse physical-time fallback for the long interseismic interval. In the standard writer, `Time between graphical output = 0` already requests every step; inheriting that setting would mask the slip trigger. As an initial **first-event observation choice**, 0.1 m of slip is reasonable for production; report frame size and revisit cadence after seeing the first acceleration. Set a separate small test threshold that is actually crossed in the short test. Take at most one frame per accepted state when a step crosses several intervals. Output scheduling must not alter the dynamics or force smaller timesteps.
- The native writer checks its time/step gate before building output. Add the smallest integration point that lets a fault trigger request that native frame and learn that a frame was written. Keep fault-specific state outside generic visualization code where practical. Respect ordinary output settings when the option is off. Update the reference after any successful frame, including a time-triggered one. Serialize by stable ID so restart, rank changes and repeated steps give neither missed nor duplicate frames. Preserve existing checkpoints or give an explicit first-frame policy for old checkpoints with no output reference.
- The donor's `benchmarks/reconstructed_fault/bp3_native/server/plugin/output_schedule.h` supplies the slip semantics. Its bulk and profile schedules were separate. The historical production prm used 1 m for heavy output, 0.1 m for profiles and explicitly disabled bulk visualization. Enable bulk output intentionally here. A separately written fault CSV or an output-variable plugin alone does not produce the requested mesh frames.
- Demonstrate accumulation through multiple small steps, a moving maximum, coincident triggers, a rejected attempt and a split restart with the same frame times and fields as uninterrupted output. Count frames in the PVD and open a PVTU with its pieces. Compare accepted station histories with graphical output on and off.
