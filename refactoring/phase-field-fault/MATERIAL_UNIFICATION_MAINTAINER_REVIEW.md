# Maintainer review of the unified phase-field fault material

**Decision.** Keep the unified material. Hold the release tag for a bounded repair. The two public inputs now select the same ASPECT plugin through the normal factory. The change preserves a meaningful distinction inside the implementation. A prescribed trace carries positive slip speed in the chosen shear sense. A growing strip carries a signed midpoint rate, native tensors and its own accepted state. Combining those histories or their integrators would obscure the numerical contracts.

Reviewed `YiminJin/aspect:pf-rsf` from `6466cfe6130e5ea2d1324466b4c530b917247961` through `754e62c4d2d52220e50b52411cec87fdd11a41a1`. The installed-run recap names production commit `4472fbcf6`. I verified that the remaining commits leave `source/` and `include/` identical. The findings below include inherited defects that matter to a freeze. [Reviewed changes](https://github.com/YiminJin/aspect/compare/6466cfe6130e5ea2d1324466b4c530b917247961...754e62c4d2d52220e50b52411cec87fdd11a41a1)

## 1. P1 · Growing friction can sample pressure at the wrong physical station

`source/material_model/phase_field_fault/strip_material_history.cc:184` passes the nominal box top to the fault-graph clipping routine. ASPECT moves the actual mesh when initial topography is applied. A **constant** positive offset keeps every cell Cartesian, so the strip mesh check admits it. The fault graph then gets clipped to the nominal top, while the adiabatic model evaluates depth from the displaced top. This can silently change normal compression, signed slip rate and the pressure entering direction selection. The mature formulation already rejects this input. The flaw predates unification. [Pressure station](https://github.com/YiminJin/aspect/blob/754e62c4d/source/material_model/phase_field_fault/strip_material_history.cc#L184) · [Mesh displacement](https://github.com/YiminJin/aspect/blob/754e62c4d/source/geometry_model/box.cc#L119) · [Depth](https://github.com/YiminJin/aspect/blob/754e62c4d/source/geometry_model/box.cc#L261)

I reconstructed the first pressure evaluation for the 30° seed in the 2 m × 1 m box. Raise the flat top by 0.02 m, retain the seed coordinates, and select the existing affine pressure law of 200 Pa plus 50 Pa per metre of depth. Strip 8 still intersects the box. Clipping at 1.00 m puts its station at y = 0.96922716 m and gives **202.538642 Pa**. Clipping at the actual 1.02 m puts it at y = 0.97922716 m and gives **202.038642 Pa**. These are independent geometry calculations. Both archived public examples have zero topography.

**Repair before freeze.** Apply the mature formulation’s zero-initial-topography requirement to growing mechanics at startup, identify the offending setting, and add one actual executable run with constant nonzero topography. It should stop before publishing the first frame. Retain the zero-topography affine-pressure control. Supporting topography would require a separate geometry qualification.

## 2. P2 · An existing material extension can silently lose its rheology

Before this change, a plugin derived from the mature `PhaseFieldFault` could override `bulk_viscosity(x)` to implement a layer. Selecting midpoint phase with that plugin failed admission. Now inherited `parse_parameters()` admits strip mechanics for any such top-level subclass. Both ordinary strip evaluation and the midpoint solve use the scalar viscosity in `strips->maxwell()`. The override never runs. An unchanged extension can therefore start successfully with homogeneous viscosity. The in-tree layered, ridge and transfer plugins acquired individual mode guards. An independently maintained extension does not acquire those guards. A related detail is that the compatibility code treats **every** growing material name other than `phase field fault` as historical and discards the Simple viscosity alias. [New selection](https://github.com/YiminJin/aspect/blob/754e62c4d/source/material_model/phase_field_fault.cc#L360) · [Strip evaluation](https://github.com/YiminJin/aspect/blob/754e62c4d/source/material_model/phase_field_fault.cc#L197) · [Layered guard](https://github.com/YiminJin/aspect/blob/754e62c4d/benchmarks/layered_moving_fault/layered_moving_fault.cc#L233) · [Alias rule](https://github.com/YiminJin/aspect/blob/754e62c4d/source/material_model/phase_field_fault/input_compatibility.cc#L226)

**Repair before freeze.** Keep the built-in canonical and historical registrations working. Make growth an intentional contract for a derived material. Preserve rejection for a trace-only SDK extension and attach historical input semantics to the registrations that actually require them. Test a material that overrides only the viscosity, plus the historical strip selector. No extra user-visible mode parameter is needed.

The new read-only strip API also needs a lifetime guarantee. On a fresh run `uses_growing_strips()` is already true after parsing, but `sections()` dereferences a null geometry until the first `begin_attempt()`. An observer calling `strip_history().sections()` during its own initialization can crash. Document when the rules become available and make premature access give a checked diagnostic. The default protected trace viscosity and exterior-stress hooks likewise need their active-mode and transport preconditions stated or guarded. [Geometry accessor](https://github.com/YiminJin/aspect/blob/754e62c4d/include/aspect/material_model/phase_field_fault/strip_material_history.h#L122) · [First initialization](https://github.com/YiminJin/aspect/blob/754e62c4d/source/material_model/phase_field_fault/strip_material_history.cc#L203) · [Trace hooks](https://github.com/YiminJin/aspect/blob/754e62c4d/include/aspect/material_model/phase_field_fault.h#L97)

## 3. P2 · The new checkpoint comparison accepts reversal of native creep history

`refactoring/phase-field-fault/results/material-unification/cross_build.py:98` uses the generic continuation comparator, which allows a 10⁻¹² absolute difference on every point column. It then tightens the three strip columns but leaves the two native accumulated shear columns at the loose tolerance. The fresh-frame checker already applies a relative-only budget to both native columns. They are checkpointed constitutive history. In particular, absolute shear also enters the check for turning a previously undamaged plane. [Restart comparison](https://github.com/YiminJin/aspect/blob/754e62c4d/refactoring/phase-field-fault/results/material-unification/cross_build.py#L98) · [Fresh-frame budget](https://github.com/YiminJin/aspect/blob/754e62c4d/benchmarks/growing_fault/check_interface.py#L35) · [Direction check](https://github.com/YiminJin/aspect/blob/754e62c4d/source/simulator/solver/midpoint_direction.cc#L192)

**Reproduced.** I exercised the comparison calls used for the 10 and 15 ms tables with synthetic native rows. A change from +10⁻¹⁴ to −10⁻¹⁴ in signed shear and from 10⁻¹⁴ to zero in absolute shear passed both continuation checks. The existing fresh-frame budget rejected both changes. The recap’s byte comparisons give stronger evidence for the particular runs already made. The defect affects what the repeatable release check will catch next time.

**Repair before freeze.** Reuse the per-field native-point comparison at requested restart clocks. Add a negative control that changes only one native history column, then rerun the two old-parent continuations without regenerating reference data.

## 4. P2 · The installed mature observer can report wrong physics or abort on valid inputs

`benchmarks/layered_moving_fault/layered_moving_fault.cc:316` assigns 10 Pa s to every material other than its own layered subclass. At lines 363–367 it also assumes 10 Pa for the shear modulus and 0.1 s for the initialization interval when subtracting the viscous stress. A user who changes the public curve’s viscosity can get a CSV labelled `eta` containing the old value. Changing the shear modulus or interval can change the reported offset even when the solver is correct. At line 326 the observer indexes `label_ages().at(i)` for every vertex. A valid state-free calculation supplies an empty vector and the first row throws. This is the installed observer recommended in the curved-example README. The published reference used RSF and the assumed constants, so those records remain usable. [Observer](https://github.com/YiminJin/aspect/blob/754e62c4d/benchmarks/layered_moving_fault/layered_moving_fault.cc#L310) · [Constitutive subtraction](https://github.com/YiminJin/aspect/blob/754e62c4d/benchmarks/layered_moving_fault/layered_moving_fault.cc#L363) · [Public instructions](https://github.com/YiminJin/aspect/blob/754e62c4d/benchmarks/fixed_fault/curved_mature/README.md#L48)

**Repair before freeze.** Use the actual material response for quantities advertised as measurements, or explicitly restrict the observer to the fixture values it can verify. Handle absent age before opening files or omit the age column for that law. Keep the existing RSF schema and frozen comparisons. Exercise the ordinary material with changed Maxwell values and a separate state-free input without an initial-age column.

## Smaller changes worth including

Today the error tells a user who already selected `phase field fault` to use the “growing fault material.” The negative test pins that wording. ## Verification and freeze boundary

I fetched the remote branch, checked the five commits, and traced factory selection, parameter declarations, material outputs, solver dispatch, acceptance, checkpoint readers and observers. I reran the public checker on the unpacked **retained mature archive** at 0, 12.5 and 25 ms, with five labels and 2,304 native samples per frame. The independent curved-field reconstruction agreed to 2.22 × 10⁻¹⁶ in phase. The computed rotated parent shear agreed to 6.16 × 10⁻¹⁷ Pa. The reported 3.97675% bend deficit remains a documented property of the transfer. The checkout here has no installed ASPECT/deal.II build, so the candidate’s compiled MPI runs, legacy checkpoint continuations and 2,605 Release assertions are evidence from the submitted qualification record. I did not reproduce those native runs. [Qualification record](https://github.com/YiminJin/aspect/blob/754e62c4d/refactoring/phase-field-fault/results/material-unification/README.md)

Use the existing implementation thread for these repairs and the existing review thread for the resulting delta. Rebuild affected SDK plugins and rerun the public curve, the nine-strip constant and affine cases, and the unchanged old-parent continuations. Keep their original tolerances and archive identities. With those checks and the targeted negative cases passing, I would freeze the unified implementation as the baseline for the next experiments. A full-size fresh BP3 run and a gravity-loaded regional case each still have their own qualification requirements.
